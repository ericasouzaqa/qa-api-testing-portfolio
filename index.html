01 / Comece aqui

Três ideias que organizam qualquer teste de API.

Se esta for a sua primeira vez, pense na API como uma porta de comunicação entre sistemas. O teste verifica se essa conversa segue o combinado.

01

Request

É o pedido enviado pelo cliente. Observe método, URL, parâmetros, headers, autenticação e body.

POST /users Content-Type: application/json
02

Response

É o retorno do servidor. Valide status code, headers, estrutura, tipos, valores e regra de negócio.

201 Created { "id": 42, "name": "Erica" }
03

Contrato

É o acordo sobre como a API deve funcionar. Swagger/OpenAPI ajuda a localizar operações, parâmetros e respostas.

GET /users/{id} 200 | 404 | 422

02 / Método de trabalho

Um teste de API pode ser explicado em quatro passos.

O fluxo abaixo serve para um exercício no Postman, um teste automatizado em Cypress ou uma validação feita durante uma entrega.

01

Ler

Encontre no requisito ou no Swagger o comportamento que precisa ser comprovado.

02

Preparar

Separe ambiente, dados, autenticação e a requisição que representa o cenário.

03

Validar

Compare resultado obtido e resultado esperado, incluindo cenários positivos e negativos.

04

Automatizar

Transforme verificações repetitivas em scripts, sem esconder a regra que está sendo testada.

05 / Exemplo pequeno

Uma assertion deve dizer qual regra está sendo verificada.

No Postman, o script abaixo não testa “tudo”. Ele verifica duas coisas específicas: o status HTTP e a presença de um campo. Esse recorte deixa o resultado fácil de ler e manter.

  • O status esperado está explícito.
  • O JSON é lido antes de validar o campo.
  • A mensagem do teste explica a intenção.
Postman · Tests 
pm.test("Status esperado", function () {
  pm.response.to.have.status(200);
});

const body = pm.response.json();

pm.test("Resposta possui um id", function () {
  pm.expect(body.id).to.exist;
});
